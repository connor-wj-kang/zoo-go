# 学籍认证方案

## 1. 推荐方案

当前版本采用“学信网在线验证报告 + 人工审核”的 MVP，不爬取学信网，也不要求用户提供学信网密码。

```text
学生提交姓名、学校、学号、入学年份、在线验证码
  -> UNVERIFIED / REJECTED / EXPIRED 可提交
  -> PENDING（锁定申请，禁止重复提交）
  -> 运营登录学信网核对姓名、学校、学号和报告有效期
  -> VERIFIED（设置认证到期时间）
     或 REJECTED（填写明确驳回原因，可重新提交）
  -> 到期后自动变为 EXPIRED，禁止新报价
```

只填写学校名称不能证明学籍。真正的审核依据必须是学信网报告中的在线验证码或其他合规数据源返回的核验结果。

## 2. 当前实现

学生端提交字段：

| 字段 | 说明 |
|---|---|
| `realName` | 与学籍报告一致的姓名 |
| `school` | 学校名称 |
| `studentNo` | 学号 |
| `major` | 专业，选填 |
| `enrollmentYear` | 入学年份 |
| `chsiCode` | 学信网在线验证码，服务端会统一转大写并生成哈希 |

后端保证：

- 一个用户同一时间只能有一条 `PENDING` 申请。
- 同一个在线验证码只能绑定一个 `PENDING` 或 `VERIFIED` 账号。
- 审核通过后写入认证有效期。
- 过期认证不能提交新报价；已有订单不因认证过期而中断。
- 驳回必须填写原因，学生可修改资料后重新提交。
- 在线验证码只出现在管理员审核接口，不返回给宠物主人或社区接口。

## 3. 管理接口

所有管理员接口都需要请求头：

```text
X-Admin-Token: <ADMIN_TOKEN>
```

查看待审核申请：

```bash
curl 'http://127.0.0.1:8080/v1/admin/student-verifications?status=PENDING' \
  -H 'X-Admin-Token: dev-admin'
```

审核通过。`validUntil` 可省略，默认一年；也可以按报告有效期或预计毕业时间设置：

```bash
curl -X POST 'http://127.0.0.1:8080/v1/admin/student-verifications/<申请ID>/approve' \
  -H 'X-Admin-Token: dev-admin' \
  -H 'Content-Type: application/json' \
  -d '{"validUntil":"2027-07-01"}'
```

审核驳回：

```bash
curl -X POST 'http://127.0.0.1:8080/v1/admin/student-verifications/<申请ID>/reject' \
  -H 'X-Admin-Token: dev-admin' \
  -H 'Content-Type: application/json' \
  -d '{"reason":"在线验证码已失效，请重新申请学籍报告"}'
```

旧接口 `POST /v1/admin/students/<用户ID>/approve` 仍保留，用于兼容已有调用，默认通过该用户最新一条待审申请并设置一年有效期。

## 4. 运营审核标准

1. 打开学信网在线验证报告验证页面，核对在线验证码。
2. 姓名、学校、学号必须与报告一致。
3. 报告必须覆盖当前日期，过期报告直接驳回。
4. 入学年份与报告或学号规则明显冲突时驳回。
5. 同一验证码对应多个账号时，只允许最早提交的申请继续审核。
6. 驳回原因必须可执行，例如“学号不一致”“报告已过期”，不要只写“审核失败”。
7. 审核完成后记录管理员身份和时间；生产环境应接入后台 RBAC 操作审计。

## 5. 安全与合规

- 不采集学信网账号和密码，只采集一次性或有时效的在线验证码。
- 当前 SQLite 版本为 MVP，生产环境应对姓名、学号、验证码加密存储，并限制数据库访问。
- 管理员令牌目前是静态 `ADMIN_TOKEN`，生产环境必须改为管理员账号、RBAC、二次认证和操作审计。
- 管理接口应增加限流、IP 白名单或内网访问控制。
- 学籍资料保留时间、删除流程和用户授权文本需要法务确认。
- 学籍认证不等于实名认证和年龄认证。上线前仍需通过持牌实名服务商完成身份证实名与 18 岁校验。

## 6. 后续接入自动核验

如果业务量上来，可以把人工审核替换为合规服务商接口，但保持当前状态机和权限边界不变：

```text
提交材料 -> 调用服务商核验 -> VERIFIED / REJECTED -> 保存服务商流水号与核验摘要
```

服务商必须能够提供学籍或教育状态核验能力。不能假设学信网向普通企业开放个人学籍查询接口，也不能通过爬虫、模拟登录或购买来源不明的数据绕过授权。

实名认证、年龄校验和学籍核验应拆成独立能力：即使学籍核验通过，也只有在实名和年龄校验都通过后才允许报价。
